# bgp-routes

Собирает списки IPv4-префиксов из разных источников, разрешает конфликты между ними по приоритету
и отдаёт результат для **bird2**: по файлу на лист (`out/<лист>.txt`) и сгенерированный `out/protocols.conf`
(протоколы `static` + фильтр экспорта с community). Роутер (VyOS) по community выбирает next-hop.

    источники (importer) -> приоритеты и вычитание -> out/<лист>.txt + out/protocols.conf -> birdc configure

Требования: Python 3.11+ (только стандартная библиотека). IPv6 не поддерживается (отбрасывается).

## Быстрый старт

    cd /opt/bgp-routes
    ./bgp-routes check                  # проверить config.toml
    ./bgp-routes run --dry-run          # посчитать, ничего не писать
    ./bgp-routes run                    # записать out/*.txt и out/protocols.conf
    ./bgp-routes run --reload           # + применить в bird (configure с автооткатом и проверкой)

## Команды

| Команда | Что делает |
|---|---|
| `run` | запускает импортёры, считает листы, пишет `out/`. Ключи: `--dry-run` (ничего не писать), `--reload` / `--no-reload` (применить в bird; по умолчанию берётся из `[bird].reload`), `--no-notify` (без Telegram), `--force` (игнорировать защиту от дрейфа размера), `--only ЛИСТ...` (пересчитать только эти листы, остальные не трогаются) |
| `reload` | применить в bird уже записанные `out/*.txt` без пересчёта |
| `check` | проверить `config.toml` (ключи, типы, regex, community) |
| `explain IP` | показать, в каких листах лежит IP, какое принято решение (самый длинный префикс) и откуда он взялся в сырых данных |
| `report ЛИСТ` | для `as_select`: сколько AS и префиксов даёт каждое правило (удобно ужесточать ключевые слова) |

Общий ключ `-c путь/config.toml` задаёт другой конфиг.

Коды возврата `run`/`reload`: `0` - всё хорошо; `1` - фатально (ошибка конфига, превышен `max_routes`, листы не обновлены);
`2` - часть листов не обновилась (источник недоступен, дрейф размера) или не удалось применить в bird.

## config.toml: справочник

Неизвестный ключ, неверный тип, дубль `name` или `community`, битый regex останавливают запуск с понятной ошибкой
(с подсказкой при опечатке). Пути относительны каталога, где лежит `config.toml`.

### `[global]`

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `out_dir` | строка | `out` | куда писать результат (`<лист>.txt`, `protocols.conf`) |
| `state_dir` | строка | `state` | кэш скачанных файлов (`dl/`), сырые данные источников (`raw/`), состояние уведомлений |
| `bird_include` | строка | `/etc/bird/bgp-routes/out` | путь к `out/` **глазами контейнера bird2**; подставляется в `include` внутри `protocols.conf`. Лучше абсолютный: BIRD может разрешать относительные include не от каталога главного конфига |
| `user_agent` | строка | `bgp-routes/1.0` | `User-Agent` при скачивании. bgp.tools просит, чтобы по нему можно было связаться с вами (можно дописать контакт) |
| `max_age_hours` | число | `48` | если скачать источник не удалось, берётся кэш не старше этого срока (с предупреждением); старше - лист считается неудачным и остаётся прежний файл |
| `max_routes` | целое | нет | суммарный лимит маршрутов по всем листам; при превышении `run` завершается с кодом 1 и **ничего не записывает** |
| `max_change_pct` | число | `30` | защита от дрейфа: если лист изменился по размеру больше чем на столько процентов (и в прошлом файле было ≥100 маршрутов), новый результат не применяется. Обход - `run --force` |
| `notify_cmd` | строка | нет | команда уведомления, получает текст первым аргументом (например `/usr/local/bin/tg-send.sh`). Пусто/нет - не уведомлять. Шлёт только при смене набора проблем (и раз в сутки, пока проблема висит), и сообщает о восстановлении |

### `[bird]`

Нужна для `run --reload` и команды `reload`. Порядок применения: `configure check` -> `configure timeout N` ->
пауза -> проверка (по каждому листу число маршрутов в файле = в протоколе bird = в экспорте на пира с нужным community;
BGP-сессия Established) -> `configure confirm`. Если проверка не прошла, подтверждения не будет, и bird сам откатит конфиг через `N` секунд.

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `birdc` | список строк | `["docker","exec","bird2","birdc"]` | как вызывать `birdc`. Без docker: `["birdc","-s","/путь/к/bird.ctl"]` (сокет лежит в смонтированном `run/`) |
| `peer` | строка | `vyos` | имя BGP-протокола в `bird.conf` (для `show route export <peer>` и проверки Established) |
| `configure_timeout` | целое | `120` | секунды до автоотката; `0` - обычный `configure` без автоотката и без confirm |
| `settle_seconds` | число | `5` | пауза после `configure` перед проверками (дать bird пересчитать экспорт) |
| `reload` | bool | `false` | применять в bird после каждого `run` (иначе только с `--reload`) |

### `[[list]]` - общие ключи (для каждого листа)

| Ключ | Тип | Обязателен | Описание |
|---|---|---|---|
| `name` | строка | да | имя листа; станет файлом `out/<name>.txt` и именем протокола bird. Только `[A-Za-z_][A-Za-z0-9_]*`, уникально |
| `importer` | строка | да | **способ получения данных**: `url_list`, `as_select` или `manual` (см. ниже) |
| `priority` | целое | да | приоритет, больше - важнее. Одновременно `preference` протокола в bird. Определяет, чей префикс остаётся при точном совпадении |
| `community` | строка | да | `ASN:значение`, например `65002:6`. Уникален среди включённых листов. По нему роутер выбирает next-hop |
| `comment` | строка | нет | свободный текст: попадает в шапку `out/<name>.txt`, в `protocols.conf` и в вывод `explain`. Удобно записать, какому next-hop соответствует лист |
| `authoritative` | bool | нет (`false`) | лист «перекрывает»: из **нижестоящих** списков выкидывается всё, что целиком лежит внутри его сетей (в том числе более специфичные префиксы). Ставьте на ручные списки и RU; такие листы должны иметь самые высокие приоритеты |
| `max_len` | целое 8..32 | нет | агрегация с потерей: префиксы длиннее `max_len` округляются до родительской сети `/max_len` (например, `/32` -> `/24`), чтобы уменьшить число маршрутов. Склейка соседних сетей (без потерь) выполняется всегда |
| `enabled` | bool | нет (`true`) | `false` - временно выключить лист (его файл не обновляется и не участвует в `protocols.conf`) |

Как разрешаются конфликты между листами (порядок: по убыванию `priority`): из листа удаляется префикс, если он
**точно совпал** с префиксом вышестоящего листа, либо целиком лежит внутри вышестоящего листа с `authoritative = true`.
Между остальными листами (в том числе с разными next-hop) решает самый длинный префикс на роутере, как и раньше.

### Импортёр `url_list` - списки по URL

Читает строки вида `1.2.3.0/24`, `1.2.3.4` (=`/32`), `route 1.2.3.0/24 ...`; комментарии (`#`) и мусор пропускаются. Поддерживаются `https://` и `file://`.

| Ключ | Тип | Обязателен | По умолчанию | Описание |
|---|---|---|---|---|
| `urls` | список строк | да | | откуда качать; префиксы всех URL объединяются. Если хоть один недоступен и кэша нет - лист неудачный |
| `min_prefixes` | целое | нет | `100` | минимум префиксов (защита от обрезанного/пустого ответа) |
| `ttl` | число (сек) | нет | `3600` | сколько кэш считается свежим |

### Импортёр `as_select` - выбор AS из дампов bgp.tools

Берёт `asns.csv` (раз в сутки) и `table.txt` (раз в 4 часа), выбирает AS и отдаёт все их IPv4-префиксы.
Правило выбора для AS: явный номер из `asn` включается всегда; иначе - подходит по `country` **или** по `names`,
и при этом не попадает под `exclude_country` / `exclude_names`.

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `country` | список строк | пусто | коды стран (колонка `cc` в `asns.csv`), например `["RU"]` - все AS этой страны |
| `exclude_country` | список строк | пусто | исключить AS этих стран (не действует на явный `asn`) |
| `asn` | список целых | пусто | точные номера AS, например `[20473]` |
| `names` | список строк | пусто | regex по названию AS, без учёта регистра, ищется **внутри** строки. Для коротких слов ставьте границы: `"\\bdell\\b"`, иначе совпадёт `Spintel`, `Inteliquent` и т. п. (в TOML внутри обычной строки обратный слэш удваивается) |
| `exclude_names` | список строк | пусто | regex: исключить AS с такими названиями |
| `min_asns` | целое | `1` | минимум выбранных AS, иначе лист неудачный (защита от изменившегося формата дампа) |
| `min_prefixes` | целое | `1` | минимум итоговых префиксов |

Подбор правил: `./bgp-routes report <лист>`.

### Импортёр `manual` - ручные списки из файлов

| Ключ | Тип | Обязателен | Описание |
|---|---|---|---|
| `files` | список строк | да | файлы относительно каталога конфига. Строка: `1.2.3.0/24` или в старом формате `route 1.2.3.0/24 blackhole; # комментарий`. Комментарий сохраняется как примечание для `explain` |

## Каталоги

    /opt/bgp-routes/
      bgp-routes            точка входа
      bgproutes/            ядро, importers/ (по файлу на тип источника), bird.py, notify.py
      config.toml           конфигурация
      manual/               ручные списки
      out/                  РЕЗУЛЬТАТ: <лист>.txt и protocols.conf (монтируется в контейнер bird2)
      state/                кэш скачанного (dl/), сырые данные (raw/ - для explain), notify.json
      systemd/              шаблоны юнитов

## Подключение к bird.conf

    include "/etc/bird/bgp-routes/out/protocols.conf";     # до protocol bgp
    protocol bgp vyos {
      ...
      ipv4 { next hop self; export filter bgp_routes_export; import none; };
    }

Каталог проекта должен быть смонтирован в контейнер как каталог (не как отдельный файл): `- /opt/bgp-routes:/etc/bird/bgp-routes`.

## Запуск по расписанию (systemd)

    cp systemd/bgp-routes.service systemd/bgp-routes.timer /etc/systemd/system/
    systemctl daemon-reload
    systemctl enable --now bgp-routes.timer
    systemctl start bgp-routes.service && journalctl -u bgp-routes -n 50 --no-pager

Юнит запускает `bgp-routes run --reload` с `WorkingDirectory=/opt/bgp-routes`. Время запуска - `OnCalendar` в `.timer`.

## Как добавить источник

1. Файл `bgproutes/importers/<имя>.py` с `NAME`, `PARAMS` (допустимые ключи и их типы), `REQUIRED` и классом `Importer(name, params, ctx)`,
   у которого метод `run()` возвращает `{IPv4Network: "примечание"}`. Скачивать - через `ctx.fetch(url, имя_файла, ttl)` (кэш и сбои обрабатываются сами),
   ошибки - исключением.
2. Блок `[[list]]` в `config.toml` с `importer = "<имя>"`. На роутере: `community-list` и `rule` в `route-map` с нужным next-hop.

## Диагностика

- `./bgp-routes explain 1.2.3.4` - кто и почему решает судьбу адреса.
- `out/<лист>.txt` в шапке содержит число маршрутов и сколько отброшено вышестоящими списками.
- `state/raw/<лист>.txt` - то, что отдал источник до округления, склейки и вычитания.
- Уведомления не приходят: проверьте `notify_cmd` и `state/notify.json` (повтор только при смене проблем или раз в сутки).
